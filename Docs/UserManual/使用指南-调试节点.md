# 使用指南-调试节点
[TOC]
## 概要
调试节点主要方便于开发过程中功能调试，以及生产环境中问题排查。通过增加自定义命令，实现自定义功能。常用调试功能主要有：
- 模拟事件触发
- 实时状态查询

## 引言
在 `sparrow` 框架中，为避免调试节点滥用，每个进程仅创建一个调试节点，统一通过 `/tmp` 目录下的命名管道与对应进程通信。

同一进程内的不同组件可通过注册模块名与命令名，实现不同模块调试命令的触发。

当前已存在的调试节点包括：`/tmp/mediatorsrv`、`/tmp/powermanagersrv`、`/tmp/propertiessrv`、`/tmp/sparrowsrv`、`/tmp/statusmonitorsrv`。

## 注册命令示例
注册和注销命令接口，框架中已封装好，使用时只需要增加命令和对应处理函数即可。以 `powermanagersrv`为例，后续不再赘述。 可参考提交 [集成SprTimerManager调试接口](https://gitee.com/LinuxTaoist/Sparrow/pulls/116/files)

1. 在进程入口增加管道监听，每个进程只需增加一次。
```
int main(int argc, const char *argv[])
{
    ...
    SprProcPrepare::GetInstance()->Init(SRV_NAME_POWER_MANAGER);
    ...
    SprEpollSchedule::GetInstance()->EpollLoop();
    return 0;
}
```

2. 注册命令处理函数
```C++
void PowerManager::RegisterDebugFuncs()
{
    SprDebugNode* p = SprDebugNode::GetInstance();
    if (!p) {
        SPR_LOGE("p is nullptr!\n");
        return;
    }

    p->RegisterCmd(mModuleName, "PowerOn",          "Send power on",        std::bind(&PowerManager::DebugSendPowerOn,   this, std::placeholders::_1));
    p->RegisterCmd(mModuleName, "PowerOff",         "Send power off",       std::bind(&PowerManager::DebugSendPowerOff,  this, std::placeholders::_1));
    p->RegisterCmd(mModuleName, "DumpCurState",     "Dump current state",   std::bind(&PowerManager::DebugDumpCurState,  this, std::placeholders::_1));
    p->RegisterCmd(mModuleName, "DumpObservers",    "Dump observers",       std::bind(&PowerManager::DebugDumpObservers, this, std::placeholders::_1));
}
```

3. 在初始化处调用注册函数 `RegisterDebugFuncs()` 即可。

4. 在组件销毁处，调用注销函数 `UnRegisterDebugFuncs()` 即可。

## 原理说明
### 原理
主要是利用 `I/O复用` 机制，将管道的读端注册到`epoll`事件中，当管道有数据可读时，触发回调函数，读取管道中的数据，根据数据内容，调用对应的处理函数。

### 封装
上述功能的原理封装成类 `SprDebugNode`、`SprProcPrepare`、`SprEpollSchedule`。
- **SprDebugNode:** 负责调试节点功能封装，包括管道的创建、注册命令、注销命令、处理命令等。
- **SprProcPrepare:** 负责进程初始化，包括进程名称的设置，。
- **SprEpollSchedule:** 负责`I/O`事件监听封装，主要包括`epoll`的创建、注册、监听、回调、数据分发等。
