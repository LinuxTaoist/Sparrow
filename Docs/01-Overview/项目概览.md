# 项目概览

## 1. 项目定位

Sparrow 是一个面向 Linux / 嵌入式设备的 C++ 中间件框架，重点为设备端软件提供稳定运行环境、模块通信能力和可观测性能力。

它强调：

- 稳定运行
- 模块解耦
- 易扩展
- 易调试
- 适配多种 Linux 嵌入式平台

## 2. 解决的问题

在设备端软件中，常见问题包括：

- 模块间耦合严重，后续扩展困难
- IO 处理和定时任务混杂，不利于维护
- 运行状态、日志和调试信息缺失
- 硬件差异和平台差异容易造成重复适配工作
- 业务功能变化较快，框架不够清晰

Sparrow 通过统一框架能力来降低这些问题带来的工程成本。

## 3. 核心能力

### 3.1 事件驱动框架

项目依赖 `Epoll` 机制处理 IO、定时器、线程任务和信号等事件，适合需要高并发和稳定执行的设备侧服务。

### 3.2 服务化通信

通过 `Binder`、消息队列和事件分发等机制，模块可以按服务边界进行协作，并保持清晰的边界和低耦合。

### 3.3 运行状态与排障能力

项目中包含日志、属性管理、调试节点和状态信息获取能力，能够在运行中更容易定位问题。

### 3.4 平台适配能力

`Hardware/` 与 `Platform/` 用于隔离平台差异、设备驱动层和运行环境差异，提升代码复用和移植效率。

### 3.5 工程结构清晰

项目结构中：

- `Core/` 负责公共框架能力
- `Components/` 放业务模块和服务组件
- `PublicAPIs/` 暴露对外能力
- `PrivateAPIs/` 放内部协议和内部通信能力
- `Debug/`、`Configs/` 提供调试与配置入口

这让业务扩展不会直接污染核心框架。

## 4. 适用对象

Sparrow 更适合开发以下类型的工程：

- Linux 嵌入式设备的软件基础框架
- 需要长期稳定运行的控制节点或网关类设备
- 模块多、功能扩展快、日志和状态观测需求明确的项目
- 需要逐步适配不同平台或不同硬件方案的工程

## 5. 不适合的场景

- 纯 Web / 桌面应用开发
- 需要跨所有平台统一运行的通用框架
- 只需要单个功能库、不需要系统级服务化结构的轻量场景

## 6. 适用一句话总结

Sparrow 适合做 Linux 设备端的基础中间件，用于统一管理事件、通信、日志、状态和平台差异，并支撑业务模块持续演进。
