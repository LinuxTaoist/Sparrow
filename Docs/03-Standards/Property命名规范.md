# Property 命名规范

## 1. 基本原则

- **清晰性**：命名应清晰表达属性的用途和含义，避免模糊不清的名称
- **一致性**：项目内保持命名风格统一
- **简洁性**：在保证清晰的前提下，名称应尽可能简洁
- **准确性**：准确反映属性的功能和范围

## 2. 命名格式

### 2.1 结构组成
property 命名采用层次化结构，使用点(.)分隔各个组成部分：
```
[命名空间].[模块/组件].[功能/特性].[具体描述]
```

### 2.2 命名空间前缀
根据属性的作用范围和生命周期，使用以下前缀：

- `ro.`：只读属性（read-only），通常在系统启动时设置，之后不可修改
- `persist.`：持久化属性，重启后仍然保留
- `sys.`：系统运行时属性，可能在运行过程中改变
- `ctl.`：控制属性，用于触发特定操作
- `debug.`：调试相关属性
- `vendor.`：厂商自定义属性
- `odm.`：设备制造商自定义属性

### 2.3 字符规则
- 仅使用小写字母(a-z)、数字(0-9)和点(.)
- 禁止使用下划线、大写字母和其他特殊字符
- 首字符必须是字母
- 点(.)不能连续出现

### 2.4 长度限制
- 完整属性名长度不超过31个字符
- 每个层次部分应尽可能简短，通常不超过8个字符

## 3. 命名规范

### 3.1 模块/组件命名
- 使用模块或组件的缩写形式
- 保持与代码中模块命名一致
- 示例：`audio`、`video`、`wifi`、`bt`(蓝牙)、`gps`

### 3.2 功能/特性命名
- 使用描述功能或特性的单词或缩写
- 示例：`vol`(音量)、`freq`(频率)、`mode`(模式)、`enable`(启用)

### 3.3 具体描述命名
- 准确描述属性的具体含义和作用
- 避免使用无意义的名称如"val"、"param"等
- 示例：`max`(最大值)、`min`(最小值)、`default`(默认值)

## 4. 示例

```
// 只读属性
ro.product.model         // 产品型号
ro.build.version.sdk     // SDK版本

// 持久化属性
persist.sys.timezone     // 时区设置
persist.audio.volume     // 音频音量设置

// 系统运行时属性
sys.boot_completed       // 启动完成标志
sys.cpu.load             // CPU负载

// 控制属性
ctl.start.zygote         // 启动zygote进程
ctl.stop.media           // 停止媒体服务

// 调试属性
debug.graphics.render    // 图形渲染调试开关
debug.log.level          // 日志级别设置

// 厂商属性
vendor.camera.resolution // 相机分辨率设置
```

## 5. 注意事项

- 避免使用可能与Android系统已有属性冲突的名称
- 对于厂商自定义属性，务必使用`vendor.`前缀
- 新增属性时应在注释中说明其含义、取值范围和使用场景
- 避免过度缩写，确保名称的可读性
- 同一模块内的属性应保持命名风格一致
